¿Qué significa reducir la dimensionalidad?

Una base analítica contiene dimensiones cuando cada pedido queda descrito por varias características. En Olist hay variables numéricas sobre precio, flete, peso, volumen, cantidad de productos y plazo de entrega; algunas guardan relación entre sí. Tener más columnas no garantiza disponer de más información independiente.

El Análisis de Componentes Principales (PCA) construye nuevas coordenadas a partir de combinaciones lineales de las variables originales. La primera componente principal (CP1) representa la dirección de mayor variabilidad; la segunda recoge la mayor variabilidad restante y es perpendicular a la primera. Las siguientes componentes siguen la misma lógica. [2]

La utilidad de PCA consiste en resumir información relacionada. También puede facilitar la visualización y reducir algunas redundancias. Pero maximizar varianza no es lo mismo que maximizar capacidad predictiva: una dimensión que presenta poca variación puede conservar información importante para distinguir entregas puntuales y tardías. [2]

Cómo leer la varianza explicada

Cada componente aporta una fracción de la variabilidad total. Cuando se suman esas fracciones se obtiene la varianza explicada acumulada. Como criterio didáctico, el laboratorio conserva suficientes componentes para explicar al menos el 90 % de la varianza de las variables numéricas transformadas. El porcentaje sirve para controlar cuánta información geométrica se retiene, no para anticipar el F1 ni el Recall. [2]

En el ejemplo, conservar una sola componente explicaría el 52 %; dos componentes, el 76 %; y tres, el 90 %. No sería correcto afirmar que un modelo con tres componentes tiene una exactitud del 90 %. La primera cifra describe el espacio de variables; la segunda requeriría comparar predicciones con entregas observadas.

En el notebook de esta semana PCA se aplica únicamente a las variables numéricas. Las cuatro variables categóricas siguen una ruta de preparación independiente mediante One-Hot Encoding. La cantidad de componentes que se retengan no equivale al número total de columnas que recibe finalmente el clasificador.

SVD: la operación matemática detrás de PCA

La descomposición en valores singulares, o SVD, permite expresar una matriz como el producto de otras tres matrices. En una matriz de datos centrados, los vectores singulares indican direcciones relevantes y los valores singulares indican la magnitud de la variabilidad asociada a ellas.

Xcentrada = U Σ Vᵀ

La matriz U contiene direcciones asociadas a las observaciones, Σ contiene los valores singulares y Vᵀ permite recuperar las direcciones de las componentes en el espacio de variables. En una matriz con n observaciones, la varianza de la componente j es proporcional a sj2 / (n − 1), donde sj es su valor singular.

No es necesario realizar manualmente la factorización sobre los 24.500 pedidos. En scikit-learn, PCA(svd_solver='full') utiliza SVD para calcular las componentes. Conviene comprender la relación: SVD es una herramienta algebraica; PCA es un método estadístico que utiliza esas direcciones para representar los datos. [2]

import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

# Ejemplo didáctico independiente de Olist
X = np.array([[10, 3], [12, 4], [14, 5],
              [16, 7], [18, 8], [20, 9]])
X_esc = StandardScaler().fit_transform(X)

pca = PCA(n_components=2, svd_solver='full')
pca.fit(X_esc)
print(pca.explained_variance_ratio_)
print(pca.components_)

El código permite observar dos arreglos. explained_variance_ratio_ representa la fracción de varianza atribuida a cada componente. components_ muestra los pesos de las variables originales dentro de las componentes. Un peso grande no implica causalidad ni convierte la componente en una variable física nueva. [2]

El orden de las transformaciones importa

Las variables no comparten las mismas unidades. Por ejemplo, peso_total_g se registra en gramos y cantidad_items corresponde a un conteo. Si se aplica PCA directamente a las magnitudes originales, las variables de mayor escala pueden dominar la variación numérica. [2]

La preparación utilizada en el laboratorio sigue este orden: imputación de faltantes, estandarización y aplicación opcional de PCA para las variables numéricas. La ruta categórica imputa la categoría más frecuente y aplica One-Hot Encoding. Después, ambas rutas alimentan la regresión logística.

La imputación no debe aprender sus medianas a partir de toda la muestra, ni el escalamiento puede utilizar las medias de validación. En ambos casos aparecería fuga de información: la representación del entrenamiento habría recibido datos que solo deberían estar disponibles al evaluar el modelo. Los objetos Pipeline y ColumnTransformer ayudan a conservar el orden y separar ambas rutas. [4]

El significado de fit y transform

fit aprende parámetros a partir de los datos, por ejemplo una mediana, una desviación estándar o una dirección de PCA. transform aplica a otros registros esos parámetros previamente aprendidos. Por eso, dentro del experimento, las transformaciones se ajustan sobre entrenamiento y luego se aplican a validación.

Esta precaución también afecta la disponibilidad de las variables: la fecha real de entrega y los días efectivamente transcurridos pueden utilizarse para construir el objetivo, pero no como predictores al momento de la compra. Lo mismo ocurre con una reseña publicada después de recibir el producto. [1] [4]

Sobreajuste: cuando el modelo aprende demasiado del entrenamiento

Un clasificador puede reproducir bien los patrones de la muestra utilizada para ajustarlo y funcionar peor frente a registros nuevos. Este comportamiento se conoce como sobreajuste. El problema no se resuelve automáticamente reduciendo variables: una representación más pequeña puede ayudar, no cambiar el desempeño o eliminar información útil. [2] [3]

La regresión logística aprende coeficientes que vinculan los predictores con la probabilidad estimada de retraso. Una penalización L2 limita la magnitud de esos coeficientes. El objetivo es desincentivar soluciones excesivamente sensibles a las particularidades de los datos de entrenamiento. [3]

Pérdida del modelo + λ × Σ wj2

En esta expresión, wj representa el coeficiente de una variable y λ controla la contribución de la penalización. Es una representación conceptual de regularización L2; la formulación exacta depende del algoritmo y su implementación.

En LogisticRegression el parámetro C controla inversamente la intensidad de regularización: valores pequeños producen una penalización más fuerte y valores grandes permiten mayor libertad a los coeficientes. No debe confundirse con la letra C utilizada en la matriz de confusión. [3]

Valor de CLecturaRiesgo o beneficio posible
0.1Regularización más fuertePuede controlar inestabilidad, pero también reducir el ajuste a señales útiles.
1.0Valor de referencia del ejercicioPermite un punto común para comparar con y sin PCA.
10.0Regularización más débilPuede mejorar el ajuste o incrementar la sensibilidad al entrenamiento.

En las configuraciones de esta semana también se usa class_weight='balanced'. Ese ajuste da más peso a la clase menos frecuente durante el aprendizaje. No elimina por sí solo el desbalance ni obliga al modelo a obtener mejor precisión. Por ello, se mantienen los mismos pesos de clase y el umbral de clasificación 0,50 durante los cuatro experimentos.

La bitácora de experimentos

Una tabla de resultados debe registrar el ID, la semilla, la huella de la muestra, el preprocesamiento, la configuración del modelo, las métricas de validación y el costo ilustrativo. Si una modificación mejora F1 pero aumenta los falsos negativos, esa situación debe quedar visible; no basta con etiquetar el resultado como mejor.

La búsqueda automatizada de hiperparámetros, por ejemplo mediante GridSearchCV, puede ser útil en ejercicios de mayor alcance. La actividad actual utiliza una comparación controlada de configuraciones para que se comprenda qué se modifica y por qué. Repetir muchas pruebas sobre la misma validación termina adaptando las decisiones a ese conjunto; para búsquedas extensas es preferible emplear validación cruzada dentro de entrenamiento y conservar datos independientes para comprobar las elecciones. [4]

¿Un modelo mejora si tiene mayor Accuracy?

En clasificación binaria se distinguen cuatro resultados. Un verdadero positivo (VP) es un pedido tardío correctamente señalado; un falso negativo (FN) es un pedido tardío que el modelo considera puntual; un falso positivo (FP) es un pedido puntual señalado como tardío; y un verdadero negativo (VN) es una entrega puntual correctamente reconocida.

MétricaQué resumePor qué importa en Olist
AccuracyProporción total de aciertos.Puede ser alta incluso si no se detecta la clase minoritaria.
PrecisionVP / (VP + FP).Indica cuántas alertas de retraso corresponden a retrasos reales.
RecallVP / (VP + FN).Indica qué proporción de los pedidos tardíos se logra identificar.
F1Media armónica de Precision y Recall.Ofrece un equilibrio resumido entre falsas alertas y retrasos no identificados.
Average Precision (AP)Resumen de la curva Precision–Recall a distintos umbrales.Evalúa el ordenamiento de pedidos por probabilidad estimada, sin limitarse al umbral de 0,50. [5]

Las métricas no responden todas a la misma pregunta. Si un equipo de logística tiene capacidad de revisar pocos pedidos, le puede interesar evitar un número excesivo de alertas. Si la consecuencia de ignorar una entrega tardía es mayor, podría priorizar Recall y aceptar más falsos positivos. La decisión depende de la finalidad y de los costos asociados. [5]

Un ejemplo con costos

Para el laboratorio se utiliza un supuesto didáctico: R$ 8 por falso positivo y R$ 35 por falso negativo. El costo estimado se calcula como 8 * FP + 35 * FN. Las cifras no proceden de una contabilidad real de Olist; se utilizan para analizar cómo una métrica puede traducirse en un criterio empresarial. [1]

En el ejemplo, A produce 100 FP y 50 FN, mientras B produce 135 FP y 30 FN. El costo calculado es R$ 2.550 para A y R$ 2.130 para B. Esto no demuestra que B sea universalmente superior: la comparación depende de que los costos supuestos, la muestra y el umbral sean pertinentes. Tampoco incluye el costo fijo de operar un sistema real de alertas.

Para comparar costos, mantenga la misma partición de validación y el mismo umbral. Si se modifica el umbral, ese cambio debe tratarse como otro experimento. Una diferencia numérica pequeña en métricas o costo no demuestra, por sí sola, una mejora estadísticamente concluyente.

Kolmogorov-Smirnov: comparar distribuciones

La prueba de Kolmogorov-Smirnov (KS) para dos muestras contrasta si la distribución de una variable es compatible entre dos grupos. En esta actividad se compara valor_flete entre entrenamiento y validación. Su propósito es describir una diferencia distributiva potencial entre particiones, no seleccionar directamente el clasificador. [7] [6]

La prueba utiliza las funciones de distribución acumulada empírica (ECDF). Para cada valor x, la ECDF indica qué proporción de observaciones es menor o igual a x. El estadístico D representa la separación vertical máxima entre ambas curvas. [6] [7]

D = supx |Fentrenamiento(x) − Fvalidación(x)|

Hipótesis y lectura del valor p

La hipótesis nula, H0, plantea que la variable sigue la misma distribución poblacional en los dos grupos. La hipótesis alternativa, H1, establece que las distribuciones difieren. Como regla de decisión del laboratorio se utiliza α = 0,05. [7] [6]

ResultadoDecisión estadísticaInterpretación adecuada
p < 0,05Rechazar H0Existe evidencia de diferencia entre las distribuciones, bajo los supuestos de la prueba.
p ≥ 0,05No rechazar H0No se dispone de evidencia suficiente de diferencia. No significa que las distribuciones sean idénticas.
from scipy.stats import ks_2samp

# Ejemplo aislado con dos grupos ficticios
flete_a = [8, 10, 11, 12, 14, 15, 18, 20]
flete_b = [9, 11, 13, 14, 16, 18, 19, 24]

resultado = ks_2samp(flete_a, flete_b,
                     alternative='two-sided')
print('Estadístico D:', resultado.statistic)
print('Valor p:', resultado.pvalue)

El ejemplo permite reconocer cómo se reportan los dos valores, pero no resuelve la prueba sobre la muestra de Olist. En el laboratorio los arreglos correspondientes se obtienen directamente de las columnas train['valor_flete'] y valid['valor_flete'].

Limitaciones que deben mencionarse

La prueba KS clásica se formula para distribuciones continuas y muestras independientes. [6] En los valores monetarios pueden existir empates por redondeo a centavos o importes repetidos. Por ello, el valor p debe interpretarse con cautela si hay muchos empates; además, muestras grandes pueden detectar diferencias muy pequeñas desde el punto de vista operativo. [6]

Conviene revisar simultáneamente el valor D, las distribuciones gráficas, el tamaño de cada grupo y medidas descriptivas como mediana y cuartiles. Un valor p no informa por sí solo la magnitud del efecto. Tampoco permite concluir que dos modelos tienen el mismo desempeño, ni garantiza que la partición aleatoria sea representativa de todos los pedidos futuros.

Una distinción importante

El KS aplicado a valor_flete responde a una pregunta sobre la distribución de una variable en dos conjuntos. Precision, Recall, F1 y AP responden a preguntas sobre predicción. Son análisis complementarios, pero no intercambiables. [5] [6]

De la métrica a una conclusión defendible

La última parte de la actividad no consiste en repetir definiciones: requiere leer los resultados del notebook y sostener una elección. Una recomendación adecuada debe indicar qué cambió entre experimentos, qué sucedió con los errores y cuál es la implicación empresarial. Debe distinguir hechos observados de inferencias o supuestos.

Cuando PCA retiene pocas componentes

¿Cuántas variables numéricas se utilizaron inicialmente? ¿Cuántas componentes explican al menos el 90 % de la varianza? ¿Qué ocurrió con Recall, F1 y los falsos negativos al comparar B contra A? Si la reducción fue importante pero la predicción empeoró, la conclusión debe registrar ambas observaciones.

Cuando dos regularizaciones producen resultados parecidos

Compare C y D respecto a B. ¿La diferencia de costo es suficientemente relevante para justificar el cambio? ¿La elección se sostiene en una sola métrica o en una combinación de evidencia técnica y operativa? No atribuya a la regularización cambios que podrían deberse a otra condición no controlada.

Cuando KS no rechaza la hipótesis nula

Informe D y p, registre el tamaño de los conjuntos y explique qué comparación se realizó. Evite escribir que las distribuciones son iguales o que el modelo quedó validado. La ausencia de evidencia suficiente de diferencia no demuestra equivalencia. [6] [7]

El repositorio debe conservar las configuraciones, resultados y decisiones junto con los scripts o notebooks ejecutables. Un cambio que no produce mejora también es un resultado del experimento. Documentarlo permite comprender por qué se mantuvo o descartó una alternativa.
